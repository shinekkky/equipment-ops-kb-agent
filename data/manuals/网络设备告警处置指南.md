# 网络设备告警处置指南

> **文档性质说明**：本指南为教学演示用仿真文档，参照公开的网络运维实践与
> 通用网管告警分级惯例编写，**并非任何厂商的真实设备手册**。文中告警代码与
> 阈值均为演示用途设定，不得直接用于生产网络变更决策。

版本：V1.4　　编制：网络运维中心　　适用范围：园区级交换机与路由器

## 1 适用范围与监控指标

### 1.1 适用设备类型

| 设备类别 | 编号规则 | 典型部署位置 | 监控方式 |
|---|---|---|---|
| 接入层交换机 | SW-0x | 楼层弱电间 | SNMP + Syslog |
| 汇聚层交换机 | SW-1x | 楼宇机房 | SNMP + NetFlow |
| 出口路由器 | RT-0x | 中心机房 | SNMP + 探针 |

### 1.2 关键监控指标说明

| 指标 | 采集方式 | 采集周期 | 说明 |
|---|---|---|---|
| CPU 利用率 | SNMP OID | 5 min | 5 分钟滑动平均，反映控制面负载 |
| 内存利用率 | SNMP OID | 5 min | 含协议栈与会话表占用 |
| 端口丢包率 | 端口计数器差分 | 5 min | 出方向丢包占总发送包比例 |
| 端口错包率 | 端口计数器差分 | 5 min | CRC 校验错误比例，反映物理层质量 |
| 光模块温度 | 数字诊断 DDM | 5 min | 光模块内部温度 |
| 光模块收发光功率 | 数字诊断 DDM | 5 min | 单位 dBm，用于判断链路衰减 |

## 2 告警代码与阈值

### 2.1 告警代码对照表

| 告警代码 | 告警名称 | 关联指标 | 严重度 | 建议响应时限 |
|---|---|---|---|---|
| N201 | CPU 利用率过高 | CPU 利用率 | 中 | 4 h |
| N202 | 端口丢包率超限 | 端口丢包率 | 高 | 1 h |
| N203 | 内存利用率过高 | 内存利用率 | 中 | 4 h |
| N204 | 光模块温度过高 | 光模块温度 | 高 | 1 h |
| N205 | 链路抖动 / 频繁 Up-Down | 端口状态、错包率 | 高 | 30 min |

### 2.2 性能指标阈值

| 指标 | 正常 | 预警级 | 报警级 | 单位 |
|---|---|---|---|---|
| CPU 利用率 | < 60 | 60 ~ 80 | > 80 | % |
| 内存利用率 | < 70 | 70 ~ 85 | > 85 | % |
| 端口丢包率 | < 0.1 | 0.1 ~ 1.0 | > 1.0 | % |
| 端口错包率 | < 0.01 | 0.01 ~ 0.1 | > 0.1 | % |
| 光模块温度 | < 60 | 60 ~ 70 | > 70 | ℃ |
| 光模块接收光功率 | -3 ~ -15 | -15 ~ -20 | < -20 | dBm |

## 3 告警处置流程

### 3.1 CPU 利用率过高处置

**触发条件**：CPU 5 分钟平均利用率 > 80%（报警级，告警码 N201）。

**可能原因**：
1. 广播风暴或二层环路导致报文泛洪；
2. 路由表震荡或协议收敛频繁；
3. 大量 ARP 请求或异常扫描流量；
4. 设备遭受流量型攻击。

**处置步骤**：
1. 登录设备执行 `display cpu-usage`，确认是控制面、数据面还是管理面占用高；
2. 查看接口流量排行，定位是否存在异常突增端口；
3. 检查生成树状态，确认无环路，必要时启用 BPDU 保护与根保护；
4. 检查 ARP 表项数量是否接近上限，定位异常源 MAC；
5. 开启 CPU 防御策略，对该接口或该源 IP 进行限速；
6. 若为已知业务割接引起，记录变更单号后持续观察即可。

### 3.2 内存利用率过高处置

**触发条件**：内存利用率 > 85%（报警级，告警码 N203）。

**处置步骤**：
1. 执行 `display memory-usage` 查看各分区占用；
2. 检查会话表与 MAC 表规模，确认是否存在表项泄漏；
3. 排查是否存在历史内存告警记录，判断是缓慢泄漏还是突发占满；
4. 缓慢泄漏类问题应在业务窗口重启对应进程或整机重启，并升级软件版本；
5. 突发占满时优先按 3.1 节排查异常流量。

### 3.3 端口丢包与错包处置

**触发条件**：端口丢包率 > 1.0%（报警级，告警码 N202）。

**丢包的可能原因**：
1. 端口带宽饱和，出口队列拥塞丢弃；
2. 端口双工模式或速率协商不一致；
3. 网线、光跳线或连接器接触不良；
4. 上游设备限速或策略丢弃。

**错包（CRC 错误）的可能原因**：
1. 网线质量不达标、长度超限或水晶头压制不良；
2. 光模块与光纤类型不匹配（单模/多模混用）；
3. 光连接器端面污染或插损过大；
4. 电磁干扰源靠近线缆走线路径。

**处置步骤**：
1. 区分丢包与错包：**错包率升高几乎总是物理层问题**，丢包率升高则优先看成因是拥塞；
2. 查看端口带宽利用率，持续超过 70% 说明存在拥塞，需要扩容或做流量整形；
3. 检查双工与速率协商结果，两端不一致的改为强制配置；
4. 更换网线或光跳线，清洁光连接器端面后复测；
5. 查看光模块收发光功率，接收光功率低于 -20 dBm 时按 3.4 节处理；
6. 若错包集中在单端口，判定为该端口链路问题，可考虑更换端口验证。

### 3.4 光模块温度异常处置

**触发条件**：光模块温度 > 70 ℃（报警级，告警码 N204）。

**可能原因**：
1. 机房或弱电间环境温度过高，机柜散热不良；
2. 设备风扇故障导致机内温升；
3. 光模块与设备兼容性不佳，功耗偏高；
4. 高密度端口满配，局部热积聚。

**处置步骤**：
1. 测量机柜进风口与出风口温差，进风温度应低于 30 ℃；
2. 检查设备风扇状态与滤网积尘情况，清理滤网；
3. 查看同机框其他光模块温度，判断是环境问题还是单模块问题；
4. 单模块异常时更换模块，并核对与设备的兼容性列表；
5. 高密度部署场景下应调整模块间隔布局，避免连续满配。

### 3.5 链路抖动与频繁 Up-Down 处置

**触发条件**：端口在 10 min 内状态翻转超过 3 次（告警码 N205）。

**处置步骤**：
1. 查看接口日志，统计 Up-Down 的时间分布，判断是周期性还是无规律；
2. 周期性抖动通常与生成树收敛、链路聚合协商或光模块老化有关；
3. 检查是否启用了链路聚合但两端配置不一致，聚合成员端口会反复抖动；
4. 检查光模块收发光功率波动幅度，波动超过 3 dB 应更换模块或光纤；
5. 排除以上原因后在端口上启用 `carrier-delay` 抑制短暂抖动，并更换端口验证。

### 3.6 设备离线与不可达处置

**触发条件**：SNMP 轮询连续 3 次失败，或 ICMP 探测连续 5 次超时。

**处置步骤**：
1. 从同网段其他设备 Ping 目标，区分是设备宕机还是链路中断；
2. 确认设备电源与 PDU 状态，检查是否有断电记录；
3. 检查上游链路与光功率，排除链路侧问题；
4. 设备能 Ping 通但 SNMP 不通时，检查 ACL 是否误拦截网管地址；
5. 确认设备宕机的，按应急预案上报并安排现场恢复。

## 4 日常巡检与优化建议

### 4.1 巡检周期

| 周期 | 项目 |
|---|---|
| 每 5 min | 自动采集 CPU、内存、端口、光模块指标 |
| 每日 | 检查告警列表与未恢复告警，核对设备在线率 |
| 每周 | 备份配置文件，检查日志磁盘占用 |
| 每月 | 分析流量趋势与端口利用率，识别容量瓶颈 |
| 每季度 | 核对软件版本与漏洞公告，评估升级窗口 |

### 4.2 优化建议

1. 对汇聚层以上设备启用 CPU 与内存阈值自适应告警，避免固定阈值在不同业务模型下失准；
2. 关键链路部署双上行并配置快速收敛协议，将中断时间控制在 50 ms 以内；
3. 建立端口级基线：对丢包率、错包率建立连续 7 天的基线，偏离基线 3 倍即预警，
   可在达到绝对阈值前发现劣化趋势；
4. 光模块建议提前更换周期件，避免达到寿命末期后集中失效。

## 5 变更与应急管理

1. 任何配置变更必须走变更单审批，禁止在业务高峰时段执行；
2. 变更前必须备份当前配置，变更后核对关键路由与生成树状态；
3. 重大故障时应先恢复业务再定位根因，禁止在业务中断期间做探索性排障；
4. 所有处置动作需记录时间、执行人、命令与结果，归档至运维工单系统。
